# Как стать iOS-разработчиком

iOS-разработка — это не один навык, а связка языка Swift, интерфейсов SwiftUI, работы с данными, сетевых запросов и привычки регулярно собирать небольшие приложения. Хорошая новость: начинать можно без диплома по Computer Science и без попытки выучить всю экосистему Apple заранее.

::: tip Что запомнить
Для старта нужны крепкие основы и практика. Вам не нужно «знать весь iOS», прежде чем написать первое приложение.
:::

## Пять основных навыков

### Swift

Swift — язык, на котором описаны данные и поведение приложения. Сначала вы освоите константы и переменные, условия, циклы, функции, структуры, классы, protocols и optionals. Не пытайтесь запомнить каждую конструкцию: важнее научиться читать код, запускать его и понимать сообщения компилятора.

### SwiftUI

SwiftUI — современный фреймворк Apple для интерфейсов. Он позволяет описывать экран декларативно: вы указываете, что должно быть видно при текущем состоянии данных, а SwiftUI обновляет интерфейс. После первых 15 дней Swift вы будете готовы собирать формы, списки, навигацию и простые приложения.

### Работа с сетью и данными

Большинство реальных приложений получают JSON из API, преобразуют его в Swift-типы и показывают пользователю. На начальном уровне достаточно понимать:

- что такое HTTP-запрос и ответ;
- как `Codable` связывает JSON со Swift-моделью;
- почему сетевой запрос выполняется асинхронно;
- как показать загрузку и обработать ошибку.

### Git

Git сохраняет историю проекта. Для начала хватит команд `git status`, `git add`, `git commit`, работы с ветками и публикации учебных проектов на GitHub. Коммиты полезны не только работодателю: они позволяют без страха экспериментировать и возвращаться к рабочей версии.

### Умение доводить маленькие проекты до конца

Один законченный калькулятор полезнее пяти просмотренных курсов. Хороший учебный цикл выглядит так: изучить одну идею, повторить пример, изменить его, затем собрать небольшую вещь самостоятельно.

## Что изучать позже

UIKit, сложную архитектуру, Core Data, многопоточность и обширное тестирование полезно знать, но они не должны задерживать первый этап. Добавляйте их тогда, когда задача проекта создаёт реальную потребность.

| Навык | Когда пригодится |
| --- | --- |
| UIKit | Поддержка существующих приложений и точная интеграция со старым UI |
| SwiftData / Core Data | Долговременное хранение связанных данных |
| Тестирование | Защита важной логики и уверенный рефакторинг |
| Архитектура | Когда экранов и состояний становится трудно придерживать в голове |
| Concurrency | Сеть, файлы и тяжёлая работа без зависания интерфейса |

## Частые ошибки новичка

### Пытаться всё запомнить

Даже опытные разработчики постоянно открывают документацию. Запоминание приходит из повторения. Ваша цель — узнавать конструкцию и уметь быстро восстановить детали.

### Бесконечно менять курс

Новая подборка видео всегда кажется понятнее текущей сложной главы. Но рост начинается там, где вы останавливаетесь, разбираете ошибку и доводите упражнение до рабочего состояния.

### Только смотреть, но не печатать код

Понимание на экране обманчиво. Наберите пример самостоятельно, переименуйте значения, сломайте одну строку и прочитайте ошибку. Компилятор — часть учебного процесса.

### Сразу строить «идеальную архитектуру»

Первое приложение может быть неровным. Сначала заставьте его работать, затем найдите повторения и улучшите названия. Абстракция имеет смысл, когда решает уже видимую проблему.

### Учиться в одиночку

Показывайте код другим, задавайте точные вопросы и сравнивайте решения. Хороший вопрос содержит ожидаемое поведение, фактический результат и минимальный пример.

## Практический маршрут

1. Пройдите Day 1–15 и запускайте каждый пример в Swift Playgrounds или Xcode.
2. Сразу переходите к первому SwiftUI-проекту; Day 16–20 открывайте дальше по маршруту перед проектами, где эта теория нужна.
3. После каждого проекта добавляйте одно собственное изменение: новый экран, проверку ввода или сохранение данных.
4. Если хочется дополнительной практики, сверяйтесь с [100 Days of SwiftUI](https://www.hackingwithswift.com/100/swiftui), но продолжайте писать код, а не только читать или смотреть.
5. Храните законченные проекты в Git и пишите короткий README: что делает приложение и чему вы научились.

## Рабочая среда

Актуальные версии инструментов, базовый deployment target и правила availability собраны в единой [version policy курса](/version-policy). В самих статьях версия iOS указывается только тогда, когда она влияет на показанный API.

Не путайте четыре вещи:

- **версия Swift** определяет возможности языка и режим проверки concurrency;
- **версия Xcode** включает компилятор, SDK и инструменты;
- **SDK** задаёт API, с которыми можно собрать приложение;
- **deployment target** задаёт минимальную версию iOS, на которой приложение запустится.

Новейший SDK не заставляет поднимать deployment target: доступность отдельного API проверяется через `if #available`.

Для нативной разработки нужен Mac с актуальной публичной версией Xcode. Первые примеры можно выполнять в Playground: создайте новый Playground, вставьте код и запустите его. Не устанавливайте beta-версии Xcode во время обучения без конкретной причины — различия с уроком мешают отличать собственную ошибку от ошибки инструмента.

::: info Совет
Заведите привычку заниматься часто и понемногу. Сорок внимательных минут в день обычно полезнее одной изматывающей сессии по выходным.
:::

## Когда вы готовы делать приложение

Не ждите ощущения полной готовности. После условий, циклов и функций уже можно собрать программу командной строки. После первых экранов SwiftUI — простое приложение. Каждая следующая тема становится понятнее, когда у неё появляется место в реальном проекте.

Начните с Day 1: там мы разберём `let`, `var`, строки и числа — базовые детали почти любого Swift-кода.
